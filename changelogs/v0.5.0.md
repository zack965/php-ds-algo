# v0.5.0 — 2026-09-12

## Added

**Data structures**
- `CircularLinkedList` (`src/DataStructure/LinkedList/Single/`) — a circular singly-linked
  list: same persistent, clone-then-splice pattern as `SingleLinkedList` (reuses
  `SingleLinkedListNode`, private constructor, static factories `empty()`/`of()`/
  `fromNodes()`/`fromIterable()`/`ofObjects()`), but the tail's `next` wraps back to the head
  instead of pointing to `null`. Because there's no `null` terminator, every traversal
  (`getIterator()`, `toArray()`, `toArrayValues()`, `map()`, `filter()`, `reduce()`,
  `contains()`, `indexOf()`) is bounded by the tracked node count instead of a
  `while ($current !== null)` loop. Full insertion/removal/access/transformation/functional
  method parity with `SingleLinkedList`. 90.62% method / 99.07% line test coverage.
  Documented in the README under [CircularLinkedList](README.md#circularlinkedlist) and in
  `articles/01-single-linked-list.md`.
- `Deque` (`src/DataStructure/Queue/Deque.php`, new `IDeque` contract extending `IQueue`) —
  extends `Queue`, adding `enqueueFront()` and `dequeueTail()` to push/pop at the front too.
  100% method/line test coverage. Documented in the README under [Deque](README.md#deque) and
  in `articles/04-queue.md`.
- `BinaryTree` / `BinarySearchTree` (`src/DataStructure/Tree/`, over a shared `AbstractTree`
  base and `BinaryTreeNode`; new `ITree`/`IBinaryTree`/`IBinarySearchTree` contracts) — the
  first non-linear structures besides `Graph`. **Mutable**, like `ArrayStack`/`Queue`/the
  heaps — not the clone-then-splice persistent pattern the linked lists use.
  `AbstractTree` provides `getRoot()`, `isEmpty()`, `clear()`, `getHeight()`, `contains()`,
  `levelOrder()`/`toArray()`, `count()`, and an in-order `getIterator()` (distinct from the
  breadth-first `levelOrder()`). `BinaryTree` fills breadth-first on `insert()` (allows
  duplicate values), plus `preOrder()`/`inOrder()`/`postOrder()`, `search()`/`remove()`,
  `isFull()`/`isComplete()`/`isPerfect()`/`isBalanced()`, and `getDiameter()`.
  `BinarySearchTree` maintains BST order on `insert()`/`remove()`/`search()` (duplicates
  ignored), plus `min()`/`max()`, `predecessor()`/`successor()`, `floor()`/`ceiling()`/
  `findClosest()`, `rangeSearch()`/`countInRange()`, `kthSmallest()`/`kthLargest()`,
  `lowestCommonAncestor()`, `isValid()`, and a genuine Day-Stout-Warren `balance()` (not AVL
  rotation) that flattens an `n`-node chain down to the height of a complete binary tree with
  the same node count. 72.22%/95.91% method/line coverage on `BinaryTree`, 82.76%/95.45% on
  `BinarySearchTree`, 100%/100% on `BinaryTreeNode`. Documented in the README under
  [BinaryTree & BinarySearchTree](README.md#binarytree--binarysearchtree) and in the new
  `articles/16-binary-search-tree.md`.

**Algorithms**
- `ArraySortAlgorythmes::heapSort()` — backed by `MinHeap`: builds a heap from the input and
  extracts the minimum `size()` times. O(n log n) in every case; O(n) auxiliary space for the
  heap, `$data` itself untouched.
- `ArraySortAlgorythmes::bucketSort()` — partitions into `max(1, floor(sqrt(n)))` equal-width
  buckets by value range, sorts each bucket independently with `insertionSort()`, then
  concatenates in order. Every element is validated up front: anything that isn't an `int` or
  `float` throws `InvalidArgumentException` before any bucketing work runs. `ArraySortAlgorythmes`
  is now 100% method/line covered end to end (bubble/selection/insertion/merge/quick/heap/bucket).
- `AlgorythmesGlobalHelpers::getMinAndMax()` — single-pass min/max helper backing `bucketSort()`,
  now with its own direct test coverage (previously only exercised indirectly).
- `Zack\PhpDsAlgo\Algorithmes\Strings\KMP` — Knuth-Morris-Pratt substring search
  (`calculateLspTable()` + `run()`), closing the string-matching category gap. 100%
  method/line coverage. Documented in the README under
  [String Matching — KMP](README.md#string-matching--kmp) and in the new `articles/17-kmp.md`.
- `DijkstraAlgorithmDistance` gained its own dedicated test file (previously only exercised
  indirectly through `DijkstraAlgorithmTest`), now 100% method/line covered.

## Changed

- `Queue`'s constructor now accepts `$maxCapacity` as a second argument, defaulting to
  `PHP_INT_MAX` (effectively unbounded) instead of leaving the property uninitialized.
  `enqueue()` now checks `isFull()` (`count() >= maxCapacity`) instead of a separate
  `count() > maxCapacity` check, removing a previous one-item capacity overshoot. Both the
  constructor and `setMaxCapacity()` throw `InvalidArgumentException` if the capacity would be
  smaller than the queue's current/initial size, rather than allowing an inconsistent state.
- `BinarySearchTree::min()`/`max()`'s docblocks corrected from "O(log n) average, O(n) worst
  case" to reflect what they actually do: an unconditional O(n) breadth-first scan over every
  node, not a BST-order descent.
- PHPDoc completed across every method touched by this release that lacked one:
  `CircularLinkedList`, `AbstractTree`, `BinaryTree`, `BinarySearchTree` (including the DSW
  rebalancing internals), `Queue`, `Deque`, `IDeque`, `AlgorythmesGlobalHelpers`. Also fixed a
  pre-existing broken Markdown code fence in the README that silently swallowed the entire
  "Exceptions & Error Handling" heading and table into a literal code block.

## Fixed

- **`src/DataStructure/Tree/BinarryTree.php` / `IBinarryTree.php` were misspelled filenames**
  declaring correctly-spelled `BinaryTree`/`IBinaryTree` classes inside — a PSR-4 mismatch
  that made both completely unreachable via normal autoloading (`use
  Zack\PhpDsAlgo\DataStructure\Tree\BinaryTree;` failed with "class does not exist"). Renamed
  both files to match; no code inside either changed.
- **Every BFS-based method across `AbstractTree`/`BinaryTree`/`BinarySearchTree` crashed** —
  `contains()`, `levelOrder()`, `BinarySearchTree::min()`/`max()`, and
  `BinaryTree::isComplete()`/`insert()`/`remove()`/`search()` all built a bare `new Queue()`
  and called `enqueue()` on it without ever setting a capacity, hitting `Queue`'s previous
  uninitialized-by-default `$maxCapacity`. Resolved by the `Queue` capacity default change
  above rather than patching each of the 8 call sites individually.
- **`BinarySearchTree::isValid()` crashed with a `TypeError`** on any non-empty tree. Its
  private `inOrderCheck()` helper was declared `inOrderCheck(BinaryTreeNode $node, ...)` —
  missing the `?` every sibling recursive helper in the class has — yet was always first
  called with a leaf's `null` child.
- **`BinaryTree::isBalanced()` always returned `false`**, for every tree including an empty
  one. `checkBalance()` used the same value, `-1`, to mean both "this child is empty" (the
  recursion's base case) and "an imbalance was found downstream," so a leaf's two empty
  children looked identical to a detected imbalance and that false signal propagated to the
  root. Fixed by making an empty subtree's height `0` instead of `-1`, freeing `-1` to mean
  only "imbalance found."
- **`BinaryTree::getDiameter()` was off by one edge.** `calculateHeight()` combined child
  heights as `leftHeight + rightHeight + 1`; reconciled against the shared height convention
  (empty `-1`, leaf `0`, else `1 + max(...)`), reaching a leaf on each side costs one more
  edge than that, so the correct combination is `leftHeight + rightHeight + 2`.
- **`CircularLinkedList::insert()` computed the wrong tail for a genuine middle insert**
  (`0 < $index < length`) — it walked forward using the *old* length instead of the new
  (one-longer) one, landing one node short. The chain itself, walked by hand from the head,
  was still correct and wrapped around properly; only the list's own tracked `$tail`
  reference (and therefore `getTail()`) was wrong, no longer satisfying "tail's `next` is the
  head." `insertBeforeNode()`/`insertAfterNode()` (which delegate to `insert()`) inherited the
  same bug for any target that wasn't the head or the tail.
- **`ArraySortAlgorythmes::bucketSort()` threw `DivisionByZeroError` on all-identical *float*
  input** (e.g. `[2.5, 2.5, 2.5]`). The zero-range guard compared `$range === 0`, but
  subtracting two floats produces a `float` `0.0`, and `0.0 === 0` is `false` in PHP — so the
  guard never caught a float zero-range, falling through to divide by a zero-width bucket.
  Fixed by comparing loosely (`$range == 0`) at the point that actually assigns each value to
  a bucket. All-identical *int* input (e.g. `[5, 5, 5]`) was never affected, since subtracting
  two ints stays an `int`. (The other, earlier `$range === 0` check — computing
  `$bucketWidth` — was left as strict comparison; it's now purely a harmless dead value in the
  float-zero-range case, since every element takes the fixed branch before `$bucketWidth`
  would ever be used.)
